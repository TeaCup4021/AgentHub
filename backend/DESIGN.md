# 登录页前端方案设计文档

## 1. 技术栈选择

| 技术 | 选择 | 理由 |
|------|------|------|
| HTML5 | 语义化标签 | 结构清晰，SEO友好 |
| CSS3 | 原生 + Flexbox/Grid | 无需额外依赖，加载快，现代CSS支持响应式 |
| JavaScript | 原生 ES6+ | 简单页面无需框架，减小包体积，直接DOM操作 |
| 字体图标 | Font Awesome (CDN) | 图标轻量，使用广泛，CDN加速 |

**不选框架的理由：** 登录页只有单一功能、无复杂状态管理，使用React/Vue会增加构建步骤和包体积（~30KB+），对首屏加载有负面影响。纯三件套即可胜任。

### 布局要点
- **全屏居中**：使用 Flexbox 实现垂直 + 水平居中
- **卡片式表单**：带阴影/圆角的白色卡片浮在渐变背景之上
- **表单宽度**：max-width: 400px，桌面/移动端自适应
- **间距**：使用 8px 基准网格，视觉呼吸感

## 4. 交互流程

```
用户打开页面
    │
    ├── 自动聚焦到邮箱输入框
    │
    ├── 用户输入邮箱 → 实时格式校验（oninput）
    │   ├── 格式正确 → 显示绿色勾 ✓
    │   └── 格式错误 → 显示红色提示 "请输入有效的邮箱地址"
    │
    ├── 用户输入密码 → 实时长度校验（oninput）
    │   ├── 长度≥6 → 显示绿色勾 ✓
    │   └── 长度<6 → 显示 "密码至少6位"
    │
    ├── 用户点击"显示密码"图标 → 切换 input type (password↔text)
    │
    ├── 用户点击"登录"
    │   ├── 校验全部通过 → 按钮显示 loading 动画
    │   │   ├── (模拟) 请求发送中... → 2秒后返回成功
    │   │   │   ├── 成功 → 绿色提示 "登录成功！即将跳转..."
    │   │   │   └── 失败 → 红色提示 "账号或密码错误"
    │   │   └── 恢复按钮状态
    │   └── 校验未通过 → 滚动到第一个错误字段 + 高亮
    │
    └── 用户按 Enter → 等同点击登录按钮
```

## 5. 验证规则

| 字段 | 规则 | 错误提示 |
|------|------|---------|
| 邮箱 (Email) | 必填；格式匹配 email regex | "请输入邮箱地址" / "请输入有效的邮箱地址" |
| 密码 (Password) | 必填；长度 ≥ 6 位 | "请输入密码" / "密码至少需要6位字符" |
| 记住我 (Remember) | 可选，默认 false | 无 |

**校验触发时机：**
- 失焦 (onblur)：字段独立校验
- 实时 (oninput)：输入时即时反馈
- 提交 (onsubmit)：全量校验，阻断不合规提交

## 6. 视觉风格

- **背景**：渐变 (左上到右下) `#667eea → #764ba2`
- **卡片**：白色 `#fff`，圆角 16px，阴影 `0 10px 40px rgba(0,0,0,0.1)`
- **主色**：`#667eea`（与背景渐变呼应）
- **错误色**：`#e74c3c`
- **成功色**：`#2ecc71`
- **字体**：系统默认字体栈，无外部字体加载
- **过渡动画**：按钮 hover 缩放、loading 旋转、提示淡入

---

## 7. 响应式断点

| 断点 | 行为 |
|------|------|
| ≥768px (桌面) | 卡片居中，最大宽度 400px |
| <768px (平板/手机) | 卡片宽度 90vw，内边距缩小，背景保持 |
| <400px (小屏) | 卡片几乎全宽，Logo 缩小 |

---

## 8. 可访问性 (A11Y)

- 所有输入框有 `<label>` 关联
- 错误提示使用 `aria-live="polite"` 支持读屏
- 按钮支持键盘 Tab 导航 + Enter 触发
- 聚焦状态有清晰 outline
- 颜色对比度 ≥ 4.5:1
