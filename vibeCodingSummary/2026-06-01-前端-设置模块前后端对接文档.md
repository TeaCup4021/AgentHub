## 1. 模块总览

### 1.1 页面结构

```
┌──────────────────────────────────────────────────┐
│  左侧导航 (180px)          │  内容区 (flex:1)      │
│                            │                      │
│  · 外观                    │  标题栏 + 关闭按钮     │
│  · 个人信息                │  ──────────────────   │
│  · LLM 配置                │  可滚动内容区          │
│  · 安全                    │    - 外观 (主题/背景色) │
│  · Token 用量              │    - 个人信息 (表单)    │
│                            │    - LLM 配置 (providers)│
│                            │    - 安全 (修改密码)    │
│                            │    - Token 用量 (统计+图表)│
```

**路由**: `/settings`
**入口组件**: `src/components/settings/SettingsPage.tsx`
**状态管理**: `useUIStore` (主题/背景色) + `useAuthStore` (用户信息) + `useTokenUsageStore` (用量)

### 1.2 功能分类

| 模块 | 数据存储 | 后端依赖 | 对接状态 |
|------|---------|---------|---------|
| 外观（主题/背景色） | 前端 localStorage | 无 | 纯前端 |
| 个人信息 | 后端 API | `PATCH /api/v1/auth/me` | 需后端实现 |
| LLM 配置 | 前端 localStorage | 建议新增 API | 待对接 |
| 安全（修改密码） | 后端 API | `PATCH /api/v1/auth/password` | 需后端实现 |
| Token 用量 | 前端内存累加 | 建议新增 API | 待对接 |

### 2.4 LLM 配置

| 属性 | 说明 |
|------|------|
| 组件 | `LLMConfigSection` |
| 默认 Provider | `openai` (P1, 默认启用) / `anthropic` (P2, 默认启用) / `gemini` (P3, 默认禁用) |
| 每个 Provider | 启用/禁用开关、API Key 输入框 (password 类型，可切换显示)、优先级上/下移动 |

| 后端需求 | **强烈建议新增 API**（当前 localStorage 无法多端同步、apiKey 明文存储不安全） |

### 2.5 安全 — 修改密码

| 属性 | 说明 |
|------|------|
| 组件 | `SettingsPage` 内联表单 (Semi Form) |

| 失败后 | toast "密码修改失败，请检查旧密码是否正确" |
| 后端需求 | **需要实现** |

| 属性 | 说明 |

## 3. 接口需求

### 3.1 通用约定

- Base URL: `/api/v1`
- 认证方式: `Authorization: Bearer <access_token>` (由 axios 拦截器自动注入)
- Content-Type: `application/json`

**统一响应格式**:

```json
// 成功
{ "code": 200, "data": <T>, "message": "success" }

// 失败
{ "code": 400|401|403|404|422|500, "data": null, "message": "错误描述" }
```

**Token 刷新**:
- 当任意接口返回 401 时，前端自动调用 `POST /api/v1/auth/refresh?refresh_token=xxx`
- 响应: `{ "data": { "access_token": "...", "refresh_token": "...", "expiresIn": 3600 } }`
- 刷新成功后自动重试原请求；失败则清除 token 回到登录页

### 3.2 PATCH /api/v1/auth/me — 更新个人信息

**请求头**: `Authorization: Bearer <token>`

**请求体** (JSON):
```json
{
  "name": "string, 必填",
  "avatarUrl": "string, 可选, 可为空字符串"
}
```

**成功响应** (200):
```json
{
  "code": 200,
  "data": {
    "id": "user-uuid",
    "email": "user@example.com",
    "name": "新名字",
    "avatarUrl": "https://...",
    "isVerified": true
  },
  "message": "success"
}
```

**需要注意的响应**:
| 情况 | code | message |
|------|------|---------|
| 未登录 | 401 | "未授权" |
| name 为空 | 422 | "name 不能为空" |

### 3.3 PATCH /api/v1/auth/password — 修改密码

**请求头**: `Authorization: Bearer <token>`

**请求体** (JSON):
```json
{
  "old_password": "string, 必填",
  "new_password": "string, 必填, 6-128 位"
}
```

**成功响应** (200):
```json
{
  "code": 200,
  "data": { "status": "ok", "message": "密码已修改" },
  "message": "success"
}
```

**需要注意的响应**:
| 情况 | code | message |
|------|------|---------|
| 旧密码错误 | 400 | "旧密码不正确" |
| 新密码格式不合法 | 422 | "密码至少 6 位" 或 "密码最多 128 位" |
| 新旧密码相同 | 400 | "新密码不能与旧密码相同" |
| 未登录 | 401 | "未授权" |

### 3.4 GET /api/v1/auth/me — 获取当前用户信息

**说明**: 属于 auth 模块，设置页用于表单初始值填充和登录状态判断。

**成功响应** (200):
```json
{
  "code": 200,
  "data": {
    "id": "user-uuid",
    "email": "user@example.com",
    "name": "用户名",
    "avatarUrl": "https://..." | null,
    "isVerified": true
  },
  "message": "success"
}
```

### 3.5 (建议新增) LLM Provider 配置 API

**背景**: 当前 LLM 配置存储在 `localStorage`，无法多端同步，API Key 明文暴露。建议迁移到后端加密存储。

#### 3.5.1 GET /api/v1/settings/llm-providers — 获取 Provider 列表

**响应**:
```json
{
  "code": 200,
  "data": [
    {
      "id": "openai",
      "name": "OpenAI",
      "priority": 1,
      "enabled": true,
      "apiKeyConfigured": true
    },
    {
      "id": "anthropic",
      "name": "Anthropic",
      "priority": 2,
      "enabled": true,
      "apiKeyConfigured": false
    },
    {
      "id": "gemini",
      "name": "Gemini",
      "priority": 3,
      "enabled": false,
      "apiKeyConfigured": false
    }
  ],
  "message": "success"
}
```

> **注意**: 出于安全考虑，不应返回完整的 API Key。`apiKeyConfigured` 布尔值让前端显示 "已连接/未启用" 状态。

#### 3.5.2 PUT /api/v1/settings/llm-providers — 全量更新 Provider 配置

**请求体**:
```json
{
  "providers": [
    {
      "id": "openai",
      "enabled": true,
      "apiKey": "sk-...",
      "priority": 1
    },
    {
      "id": "anthropic",
      "enabled": true,
      "apiKey": "",
      "priority": 2
    }
  ]
}
```

> **后端逻辑**: `apiKey` 为空字符串时表示不更新/清除；不为空时更新并加密存储。优先级全量覆盖（按数组顺序）。

#### 3.5.3 前端字段映射

```typescript
interface LLMProvider {
  id: string;       // Provider 唯一标识: "openai" | "anthropic" | "gemini"
  name: string;     // 展示名称
  apiKey: string;   // API Key (前端输入，后端加密存储)
  priority: number; // 优先级 (1-based, 越小越优先)
  enabled: boolean; // 是否启用
}
```

### 3.6 (建议新增) Token 用量查询 API

**背景**: 当前用量数据纯前端在内存中累加（流式结束 → `addUsage()` → `useTokenUsageStore`）。刷新页面即丢失，无法统计真实跨会话用量。

#### 3.6.1 GET /api/v1/settings/token-usage — 查询 Token 用量

**Query 参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|:---:|------|
| `from` | string | 否 | 起始日期, ISO date 格式 (如 `2026-05-01`)，默认本月 1 日 |
| `to` | string | 否 | 截止日期，默认今天 |

**响应**:
```json
{
  "code": 200,
  "data": {
    "summary": {
      "totalInputTokens": 1234567,
      "totalOutputTokens": 456789,
      "estimatedCost": 12.34
    },
    "events": [
      {
        "timestamp": "2026-05-15T10:30:00Z",
        "conversationId": "conv-uuid",
        "conversationTitle": "前端性能优化",
        "agentName": "Claude Sonnet",
        "model": "claude-sonnet-4-6",
        "inputTokens": 10000,
        "outputTokens": 2500,
        "estimatedCost": 0.07
      }
    ]
  },
  "message": "success"
}
```

#### 3.6.2 前端字段映射

```typescript
interface TokenUsage {
  conversationId: string;
  conversationTitle: string;
  agentName: string;
  inputTokens: number;
  outputTokens: number;
  totalTokens: number;       // inputTokens + outputTokens (后端计算或前端聚合)
  estimatedCost: number;     // 按计费单价计算
}

interface TokenEvent {
  timestamp: string;         // ISO 8601
  conversationId: string;
  conversationTitle: string;
  agentName: string;
  inputTokens: number;
  outputTokens: number;
  estimatedCost: number;
}
```

## 4. 状态联动

### 4.1 主题 → 全局 UI 联动

```
setTheme(theme)
  → useUIStore.setTheme()
    → localStorage.setItem("agenthub-theme", theme)
      → index.css :root CSS 变量切换
        → Semi Design ConfigProvider theme 切换
          → 所有组件即时重渲染
```

**暗色主题下 bgColor 不生效**：渲染时判断 `theme === "dark" || (theme === "system" && prefersDark)` → 跳过 bgColor 应用。

### 4.2 个人信息 → Store 回写

```
提交表单 → authApi.updateProfile() → PATCH /auth/me
  → 成功: res.data.data (更新后的 User) → _setAuth(user, token, refreshToken)
    → useAuthStore.user 更新 → 侧边栏头像/名称即时刷新
  → 失败: toast.error 提示，表单保持原值
```

### 4.3 LLM 配置 → Provider 开关联动

```
toggle enabled → updateProvider(id, { enabled }) → persist(updated)
  → 禁用态: opacity 0.55, 所有输入/按钮 disabled, 优先级按钮不可用
  → 启用态: 恢复交互
API Key 填写 → apiKey.length > 0 → badge 从 "未启用" → "已连接" (绿色)
```

### 4.4 Token 用量 → 图表联动

```
流式结束 → chatStore.finalizeStreamingMessage()
  → tokenUsageStore.addUsage({ conversationId, inputTokens, outputTokens, ... })
    → usageMap 累加 → TokenUsagePanel 统计数更新
    → events 追加 → TokenCharts 三张图表实时更新
```

## 5. 异常处理

### 5.1 个人信息更新失败

| 场景 | 交互 |
|------|------|
| 网络错误 / 500 | toast "更新失败，请重试"，表单保持填写内容 |
| 401 未登录 | 自动触发 token 刷新 → 重试；刷新失败则跳转登录页 |
| 422 校验失败 | 显示后端返回的 message（如 "name 不能为空"） |

### 5.2 密码修改失败

| 场景 | 交互 |
|------|------|
| 旧密码错误 | toast "密码修改失败，请检查旧密码是否正确" |
| 两次新密码不一致 | 客户端拦截，toast "两次输入的新密码不一致"，不发送请求 |
| 新密码不足 6 位 | Semi Form 内置校验拦截，"密码至少 6 位" |
| 401 | Token 刷新 → 失败则跳转登录 |

### 5.3 LLM 配置异常 (当前方案)

| 场景 | 处理 |
|------|------|
| localStorage 不可用 | 使用 `DEFAULT_PROVIDERS`，功能正常但数据不持久化 |
| 存储数据格式损坏 | `isValidProvider()` 校验失败 → 回退到 `DEFAULT_PROVIDERS` |
| JSON.parse 异常 | try/catch → 回退默认值 |

### 5.4 Token 用量异常

| 场景 | 处理 |
|------|------|
| events 为空 | 显示空状态提示："暂无近期对话记录" |
| 数据超大 | `formatNum()` 自动转为 "k"/"M" 单位 |
| 图表数据为空 | `agentData.length === 0` → 显示 "暂无数据" |

## 6. 对接优先级建议

| 优先级 | 接口 | 理由 |
|:---:|------|------|
| P0 | `PATCH /auth/password` | 安全基础功能，必须后端实现 |
| P0 | `GET/PATCH /auth/me` | 个人信息展示和修改依赖 |
| P1 | LLM Provider CRUD API | 当前 localStorage 方案安全风险（API Key 明文），且无法多端同步 |
| P2 | Token 用量查询 API | 当前内存累加不准确、刷新丢失，但功能块可独立工作 |
