## 2026-05-21

### 问题 1：React 无限重渲染 (Maximum update depth exceeded)

**现象**

浏览器控制台报错：
```
Uncaught Error: Maximum update depth exceeded. This can happen when a component
repeatedly calls setState inside componentWillUpdate or componentDidUpdate.
```

同时控制台出现：
```
The result of getSnapshot should be cached to avoid an infinite loop
```

**根因**

在 Zustand 的 `useChatStore` selector 中调用了 store 方法 `s.filteredConversations()`：

```tsx
// ❌ 错误写法
const conversations = useChatStore((s) => s.filteredConversations());
```

`filteredConversations()` 每次调用返回一个新的数组引用。Zustand 使用 `Object.is` 比较 selector 返回值，新旧数组引用不同 → 触发组件重渲染 → 再次执行 selector → 又产生新数组 → 无限循环。

**解决**

只订阅原始数据（`conversations` 数组、`searchQuery` 字符串），在组件内用 `useMemo` 做过滤：

```tsx
// ✅ 正确写法
const rawConversations = useChatStore((s) => s.conversations);
const searchQuery = useChatStore((s) => s.searchQuery);

const conversations = useMemo(() => {
  const q = searchQuery.toLowerCase();
  return rawConversations
    .filter((c) => !c.isArchived && (!q || c.title.toLowerCase().includes(q)))
    .sort((a, b) => {
      if (a.isPinned !== b.isPinned) return a.isPinned ? -1 : 1;
      return new Date(b.lastActiveAt).getTime() - new Date(a.lastActiveAt).getTime();
    });
}, [rawConversations, searchQuery]);
```

**原则**

- Zustand selector 中**只能返回**：原始值（string / number / boolean）、对象引用（需确保引用稳定）、函数引用（store 方法在创建时固化，引用稳定）
- 需要计算的派生值用 `useMemo` 在组件内处理
- 不要在 selector 中调用会产生新引用的函数

### 架构决策

采用 **React Query（服务端状态）+ Zustand（UI 状态）** 分离：
- React Query 接管所有 REST 数据（会话列表、消息历史、Agent 列表）的缓存、失效、重取

- SSE 按活跃会话管理连接生命周期，切换会话时断开旧连接、建立新连接


### 架构决策

- **流式渲染**：chatStore 管理 `streamingContent: Record<string, MessageContent[]>`，SSE token 事件追加文本、artifact 事件追加卡片，message_end 事件冻结并清除

## Mock 数据系统 (2026-05-21)

### 背景

后端尚未就绪，前端需要独立开发和验证。按 AGENTS.md 规范，Mock 数据统一放在 `src/mocks/` 目录。

### 新建文件

- `src/mocks/data.ts` — Mock 数据集：
  - 3 个 Agent（Claude Code / Codex / OpenCode）
  - 3 个 Conversation（2 个单聊 + 1 个群聊）
  - 7 条消息，覆盖 text / code / diff 三种内容类型
- `src/mocks/handlers.ts` — Axios 请求拦截器，拦截 9 个 API 端点并返回 Mock 数据：
  - GET/POST `/conversations`、GET/PATCH/DELETE `/conversations/:id`
  - POST/GET `/conversations/:id/messages`
  - GET/POST `/agents`
  - 延迟 300ms 模拟网络，CRUD 操作会修改内存数据
- `src/mocks/sse.ts` — Mock SSE 流式模拟：
  - 为每个 Agent 预设不同的回复内容（文本 + 代码卡片）
  - 模拟完整 SSE 事件序列：message_start → token... → artifact → token... → message_end
  - token 逐字输出（20-50ms 间隔），artifact 在对应位置插入
  - 返回 `abort` 清理函数
- `src/mocks/index.ts` — 统一开关：`enableMockMode()` / `disableMockMode()`

### 修改文件

- `src/lib/sse.ts` — 新增 `setMockSSE()` 注入点，`createSSEStream` 优先使用 Mock 实现
- `src/main.tsx` — 应用启动时调用 `enableMockMode()`

### 架构设计

```
main.tsx
  └── enableMockMode()
        ├── setupMockHandlers(api)      → axios request interceptor 接管 REST
        └── setMockSSE(mockSSEStream)   → sse.ts 注入点接管 SSE
```

**切换真实后端**：注释掉 `main.tsx` 中的 `enableMockMode()` 即可，ChatArea 无需改一行代码。
