## 1. 单聊模式

### 1.1 概述

单聊模式下，用户创建对话时绑定一个 Agent，整个对话过程由该 Agent 处理。

### 1.2 流程

```
用户创建单聊 → 选择 Agent → 绑定到 Conversation
              │
              ▼
用户发送消息 → POST /messages (mode=direct)
              │
              ▼
         SSE GET /stream
              │
              ├── CLI Agent (claude-code-cli / codex-cli)
              │     → _cli_sse_stream → 子进程运行本地 CLI
              │
              └── 非 CLI Agent
                    → _adk_sse_stream → build_agent_from_model()
                      → 使用 Agent 的 provider/model/system_prompt/tools
                      → ADK Runner 流式输出
```

### 1.3 关键实现

**路由逻辑** (`backend/app/api/v1/conversations.py:1027-1068`):

```python
# 单聊路由：始终使用对话绑定的 Agent，无默认回退
conv = await db.get(Conversation, conv_id)
conv_agents = 从 conversation_participants 查出绑定的 Agent

if CLI agent → _cli_sse_stream(conv_id, cli_provider, prompt)
if 非 CLI agent 且 ADK 开启 → _adk_sse_stream(conv_id, user_id, prompt, agent_model)
无绑定 Agent → 错误 "该对话未绑定任何 Agent"
```

**Agent 构建** (`backend/app/services/adk/runner.py:31-57`):

```python
def build_agent_from_model(agent_model: AgentModel) -> LlmAgent:
    # 根据 Agent 的 provider 选择模型
    provider=anthropic → get_anthropic_llm(model=agent.model)
    provider=openai 等 → get_litellm(model="openai/gpt-5.2")
    
    # 使用 Agent 配置的 system_prompt 和 tools
    return LlmAgent(
        name=_sanitize_agent_name(agent.name),  # 清理特殊字符
        model=model,
        instruction=agent.system_prompt,
        tools=ToolLoader.load(agent.tool_config),
    )
```

**CLI Agent 路由** (`backend/app/services/adk/cli_runner.py`):

| CLI Agent | 可执行文件 | IDLE 超时 |
|-----------|-----------|----------|
| Claude Code | `claude` + 参数 `-p` `--output-format stream-json` | 等 EOF |
| Codex CLI | `codex exec - -m <model> -s workspace-write` | 30s |

**@mention 升级弹窗** (`agenthub-web/src/components/layout/ChatArea.tsx:442-450`):

单聊中 @mention 外部 Agent → `MentionSwitchDialog` 弹窗 → 选择：
- 切换为单聊（仅单个外部 Agent）
- 转为群聊（合并所有 Agent）
- 仅发送给当前 Agent（忽略外部 mention）

## 2. 群聊模式

### 2.1 概述

群聊模式支持多个 Agent 协作完成任务。核心改动：支持用户指定 Planner Agent。

### 2.2 完整状态机

```
用户发送群聊消息
    │
    ├── mentions 为空 → 自动填入 conversation.agentIds
    │
    ├── 用户选了 Planner → planner_agent_id = <指定 Agent UUID>
    └── 用户未选 Planner → planner_agent_id = null

              ↓

POST /messages (mode=auto_orchestrate, mentions=[...], planner_agent_id=<uuid|nil>)
              │
              │  创建 OrchestratorTask(status=planning, planner_agent_id=<uuid|nil>)
              ▼

Phase 1: planning → _orchestrator_plan_stream
              │
              ├── planner_agent_id 有值 → Agent-based Planning
              │     └── 用指定 Agent 的 model + system_prompt 生成计划
              │
              └── planner_agent_id 为空 → Orchestrator (LLM) Planning
                    └── 用内置 Orchestrator LLM 生成计划
              │
              ▼
         plan_draft (状态) → SSE finish_reason="plan_draft"
              │
              ├── 用户通过对话修改 → POST /messages (mode=refine_plan)
              │     └── Phase 1.5: refining → _orchestrator_refine_stream
              │           └── Planner 根据反馈调整计划 → 回到 plan_draft
              │
              └── 用户点击"确认执行" → POST /messages (mode=confirm_plan)
                    └── status=confirmed
                          │
                          ├── planner_agent_id 存在 → DAG 模式执行
                          │     └── _dag_workflow_stream (WorkflowBuilder 静态 DAG)
                          │
                          └── planner_agent_id 不存在 → Coordinator 模式执行
                                └── _coordinator_stream (LLM 动态调度)
```

### 2.3 Planner 制定计划

**内置 Orchestrator (LLM)** (`backend/app/services/adk/planner.py:166-175`):

```python
async def _plan_with_orchestrator(...):
    agent = LlmAgent(
        name="orchestrator",
        model=get_deepseek_llm(),       # AGENTHUB_ORCHESTRATOR_MODEL
        instruction=计划 prompt,
        planner=BuiltInPlanner(...),
    )
    # 输出 JSON 计划 → 解析为 OrchestratorPlan
```

**Agent-based Planner** (`backend/app/services/adk/planner.py:115-123`):

```python
async def _plan_with_agent(planner_agent, ...):
    agent = build_agent_from_model(planner_agent)  # 使用 Agent 自己的模型
    agent.instruction = 计划 prompt  # 覆盖 system_prompt
    agent.planner = BuiltInPlanner(...)
    # GPT-4o / Claude Opus 等 Agent 用自己的模型处理
```

**计划 JSON 格式**:

```json
{
  "subtasks": [
    {
      "subtaskId": "s1",
      "agentId": "<uuid>",
      "agentName": "Claude Code CLI",
      "instruction": "编写 login.html",
      "dependsOn": [],
      "mode": "single_turn",
      "outputKey": "result_s1"
    }
  ]
}
```

**兜底逻辑**: JSON 解析失败 → 整个任务分配给第一个 Agent。

### 2.4 对话式修改计划

```
用户发消息修改计划
    │
    ▼
POST /messages (mode=refine_plan, plan_id=<plan_uuid>)
    │
    │ OrchestratorTask.status → refining
    ▼
SSE GET /stream → _orchestrator_refine_stream
    │
    │ planner.refine(current_plan, user_feedback, planner_agent)
    │
    │ 修改后的计划 → 新 plan_draft
    ▼
status → plan_draft (可继续迭代)
```

### 2.5 两种执行模式

| | Coordinator 模式 | DAG 模式 |
|---|---|---|
| **触发条件** | planner_agent_id 为空 | planner_agent_id 有值 |
| **调度方式** | LLM 动态调用 `request_task_<name>` | Workflow 静态依赖图 |
| **代码位置** | `conversations.py:_coordinator_stream` | `conversations.py:_dag_workflow_stream` |
| **构建器** | `CoordinatorBuilder` | `WorkflowBuilder` |
| **并行控制** | Coordinator LLM 自主决定 | `max_concurrency=3` |
| **适用场景** | 灵活、需要动态调整 | 结构化、依赖明确 |

**Coordinator 模式执行细节**:

```python
# coordinator_builder.py:35-53
CoordinatorBuilder.build(agent_models):
    sub_agents = [为每个 Agent 构建 LlmAgent]
    coordinator = LlmAgent(
        name="orchestrator",
        model=get_deepseek_llm(),
        instruction="你是智能协调者...",
        sub_agents=sub_agents,  # 通过 request_task_<name> 调用
    )
    # Coordinator LLM 自主决定执行顺序和依赖
```

**DAG 模式执行细节**:

```python
# workflow_builder.py:17-100
WorkflowBuilder.build(plan, agent_models):
    for sub_task in plan.subtasks:
        agent = LlmAgent(...)  # 每个子任务一个 Agent
        agent_map[subtask_id] = agent
    
    # 根据 depends_on 构建 Edge 连接
    for dep_id in sub_task.depends_on:
        edges.append(Edge(from=agent_map[dep_id], to=agent_map[subtask_id]))
    
    return Workflow(edges=edges, max_concurrency=3)
```

## 4. SSE 事件协议

### 单聊事件

```
message_start  { sender: {type: "agent", name: "GPT-4o"}, ... }
token          { delta: "你好", ... }
message_end    { finish_reason: "completed", ... }
error          { code: "...", message: "...", ... }
```

### 群聊计划事件

```
message_start  { sender: {type: "orchestrator", name: "GPT-4o | Orchestrator"},
                 meta: { plan: [...], planner_agent_id: "...", planner_agent_name: "..." } }
token          { delta: "{...", ... }  ← 流式 JSON 计划
message_end    { finish_reason: "plan_draft", ... }
```

### 群聊执行事件

```
message_start  { sender: {type: "agent", name: "Claude Code CLI"}, ... }
token          { delta: "页面已创建...", ... }
agent_status   { agent: {...}, status: "running" | "success" | "failed", ... }
message_end    { finish_reason: "completed", ... }
```
